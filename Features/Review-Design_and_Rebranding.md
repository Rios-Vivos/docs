# Feature: Design, UX, and rebranding delivery

**Status:** Planned/review. The existing rebranding record defines intent; this
record defines traceable delivery evidence.

**Owning repositories:** `web-page`, `system-admin`, `docs`.

**Source issues:** [design creation](https://github.com/Rios-Vivos/web-page/issues/5), [landing redesign](https://github.com/Rios-Vivos/web-page/issues/13), [activities redesign](https://github.com/Rios-Vivos/web-page/issues/15), [events redesign](https://github.com/Rios-Vivos/web-page/issues/16), [graphics](https://github.com/Rios-Vivos/web-page/issues/27), and [UX/UI map](https://github.com/Rios-Vivos/docs/issues/3).

## Required artifacts

- Approved sitemap, audience journeys, conversion goals, and source-controlled
  links to the approved Figma/wireframe artifacts.
- Component/content inventory mapping each public page to owner, locale, media,
  analytics event, and CMS source where applicable.
- Accessibility review covering keyboard flow, semantics, contrast, images,
  forms, error states, and responsive layouts.
- Usability findings and decision log showing what changed, why, and how it was
  verified with intended audiences.

## Acceptance checks

- Design links are durable and access-controlled for collaborators.
- Each redesigned public route has mobile and desktop evidence, SEO metadata,
  localized copy, and a defined empty/error state.
- Visual feedback is triaged into a reproducible issue, accepted/rejected with
  rationale, and linked to its implementation.
